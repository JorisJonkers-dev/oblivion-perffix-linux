# Tracking

Where results and findings are kept, so nothing gets lost between sessions and agents.

| File | What | How it is updated |
|---|---|---|
| [LOG.md](LOG.md) | Dated findings, decisions and lessons, newest first. One entry per finding, with links to its evidence. | By hand, after every run series, investigation or decision |
| [investigations.md](investigations.md) | Every investigation: question, status, outcome, where the write-up is | By hand when one starts, changes status or ends |
| [runs.md](runs.md) | Every benchmark run, one row per scene, plus every A/B report | Generated: `python3 linux/track.py` (never edit by hand) |
| `runs/<run>.md`, `runs/<run>.json` | A copy of each run's `report.md` and a compact `result.json` | Generated by `linux/track.py` |
| [../specs/](../specs/) | Specs with user stories; new findings that change scope go there too | By hand |

## Conventions
- **Run labels:** `<spot>-<variant>[-rN]`, for example `cs-render-off` or `own-off-vs-on`. The runner prefixes the
  folder with the date and time, so names never collide.
- **After a run series:**
  1. Run `python3 linux/track.py`.
  2. Add a LOG.md entry: what was asked, what was run (links to runs.md rows or reports), the numbers that matter, and
     the conclusion with its confidence (rounds, noise).
  3. Commit both.
- **Raw data** (MangoHud CSVs, diag ledgers) stays in `linux/results/` (git-ignored). Don't delete run folders that a LOG
  entry relies on.
- **Noise:** about ±5–10% on fps between fresh runs. Conclusions need balanced order and 2 or more rounds. Mark single-run
  results as indicative only.
